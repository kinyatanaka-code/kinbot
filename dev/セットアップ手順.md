# 自動改善のはじめ方（手順）

上から順に進めれば終わります。**30分ほど**で終わる想定です。
迷ったら、その番号だけ飛ばして先に進んでかまいません（あとから足せます）。

---

## 1. Anthropicのキーを作る（5分）

Claudeに作業してもらうための鍵です。

1. https://console.anthropic.com を開く
2. 左メニューの **API Keys** → **Create Key**
3. 名前は `kinbot-github` など
4. 出てきた `sk-ant-...` を**その場でコピー**（あとから見られません）

> お金について：使ったぶんだけの後払いです。1時間ごとに動かすと、目安は**月に数千円**です。
> Billing の画面で「使いすぎ防止の上限」を決めておくと安心です。

---

## 2. kinbot側の合言葉を決める（3分）

GitHubからkinbotのデータを読むための合言葉です。

1. 好きな文字列を決める（例：`kbt_auto_8f3k2j9x`）
2. Railway → kinbotのサービス → **Variables**
3. `API_TOKENS` があれば、末尾にカンマで足す。無ければ新しく作る

```
API_TOKENS = kbt_auto_8f3k2j9x:admin
```

すでに何か入っている場合：

```
API_TOKENS = 既存のもの:admin, kbt_auto_8f3k2j9x:admin
```

4. 保存すると、kinbotが自動で再起動します

---

## 3. GitHubに鍵を登録する（5分）

GitHub → `kinyatanaka-code/kinbot` → **Settings** → 左メニュー
**Secrets and variables** → **Actions**

### Secrets タブ →「New repository secret」

| Name | Secret |
|---|---|
| `ANTHROPIC_API_KEY` | 1でコピーした `sk-ant-...` |
| `KINBOT_TOKEN` | 2で決めた `kbt_auto_8f3k2j9x`（`:admin` は付けない） |

### Variables タブ →「New repository variable」

| Name | Value |
|---|---|
| `KINBOT_URL` | `https://kinbot-production-225f.up.railway.app` |

---

## 4. Actionsに権限を与える（2分）

GitHub → Settings → **Actions** → **General** → 下のほうの **Workflow permissions**

- **Read and write permissions** を選ぶ
- **Allow GitHub Actions to create and approve pull requests** にチェック
- **Save**

これをしないと、PRが作れません。

---

## 5. 動かす設定ファイルを置く（5分）

`.github/workflows/` の下に置きます。GitHubの画面からでも作れます。

1. リポジトリの **Add file** → **Create new file**
2. ファイル名の欄に `.github/workflows/kinbot-hourly.yml` と入力
   （スラッシュを打つと、勝手にフォルダになります）
3. 中身を貼り付けて **Commit changes**

同じやり方で、この4つを置きます。

| ファイル | 何をするか | いつ動くか |
|---|---|---|
| `kinbot-hourly.yml` | 直して、安全なら本番へ | 毎時0分 |
| `kinbot-rollback.yml` | おかしくなったとき戻す | 手で押したとき |
| `kinbot-advisor.yml` | 次にやるとよい案を出す | 平日 9/12/15/18/21時 |
| `kinbot-night.yml` | 夜にまとめて直す | 毎日 3時 |

`kinbot-hourly.yml` があれば `kinbot-night.yml` は無くてもかまいません。

---

## 6. kinbot側のスイッチを入れる（5分）

kinbot → **ツール** → **開発メモ**

### 「自動で直す（1時間ごと）」

- **1時間ごとに直す** … ✅ 入れる
- **直したものを本番に入れる** … ⬜ **最初は入れない**（PRで様子を見る）
- 入れてよい時間 … `0`〜`24`（あとで `20`〜`8` などに絞れます）
- **保存**

### 「自己点検」

- **自動で点検する** … ✅ 入れる
- **知らせ先** … Google Chatで**自分だけのスペース**を作り、そのWebhook URLを貼る
  （Chat → スペースを作成 → そのスペースの ⋮ → アプリと統合 → Webhook）
- **保存**

### 「画面の使いやすさの見直し」

- **自動で見直す** … ✅ 入れる
- **保存**

---

## 7. 試しに1回動かす（5分）

GitHub → **Actions** → 左から **1時間ごとの自動改善** → **Run workflow**

- `今回やる件数` … `1`
- `本番に入れず、必ずPRにする` … `yes`
- **Run workflow** を押す

3〜10分で終わります。緑のチェックが付いたら成功です。

### 見るところ

1. **Actionsのログ** … 「今夜の作業指示」に何が選ばれたか
2. **Pull requests** … PRができているか。中身（Files changed）を見る
3. **Google Chat（自分のスペース）** … 結果が届いているか

---

## 8. 慣れてきたら本番へ入れる

PRを何本か見て、「これなら任せられる」と思えたら、

kinbot → ツール → 開発メモ →「**直したものを本番に入れる**」を ✅ にする

これで、小さくて安全な変更は**人の確認なしで本番に入る**ようになります。

---

## 困ったときの止め方

| やりたいこと | やり方 |
|---|---|
| すぐ止めたい | kinbot → 開発メモ →「1時間ごとに直す」を ⬜ にする |
| 本番反映だけ止めたい | 「直したものを本番に入れる」を ⬜ にする |
| 入った変更を戻したい | GitHub → Actions →「巻き戻し」→ Run workflow |
| 商談中は入れたくない | 入れてよい時間を `20`〜`8` にする |

---

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| Actionsが赤くなる | ログの赤い行。多くは3の鍵の入れ忘れ |
| 「kinbotから読めませんでした」 | 2の `API_TOKENS` と3の `KINBOT_TOKEN` が同じか |
| PRができない | 4の権限設定 |
| Chatに届かない | 6の知らせ先（Webhook URL）が入っているか |
| `claude: not found` | Claude Codeの入れ方が変わった可能性。ログを見せてください |
